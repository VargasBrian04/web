CÓMO VER LA PÁGINA (2 opciones)
----------------------------------------------------------------
A) Rápido, sin instalar nada:
   - Hacer doble clic en "vista-previa.html" (vista previa estática,
     funciona sin internet ni base de datos).
   - Está sincronizada con el sitio: ingreso por rol (Docente,
     Padre/Tutor, Visitante), galería con 25 fotos y login de
     demostración.
   - NOTA: los portales con datos reales (notas, asistencia, tareas)
     solo funcionan con la opción B.

B) Sitio completo (recomendado):
   1. Instalar Node.js LTS desde https://nodejs.org/es
   2. Abrir terminal en la carpeta sitio-web\
   3. npm install
   4. Levantar la base de datos:  docker compose up -d
   5. Copiar variables:  copy .env.example .env   (y editarlas)
   6. npx prisma generate
   7. npm run prisma:migrate
   8. npm run seed
   9. npm run dev  ->  http://localhost:3000

BLOG / NOTICIAS (2026-10-04) — sistema completo con DB
----------------------------------------------------------------
- Modelo NewsPost (slug único estable, título, contenido HTML, categoría,
  imagen subida o estática, BORRADOR/PUBLICADA, fecha de publicación).
- Públicas: /noticias (4 recientes + botón Ver más), /noticias/todas
  (paginada de 9), /noticias/[slug] (lectura). Todo desde la DB con
  fallback estático si la DB cae. Los borradores jamás se ven.
- Dirección: /portal/admin/noticias (solo ADMIN) — crear con editor
  (negrita/cursiva/listas/enlace), portada PNG/JPG/WEBP ≤10MB con
  arrastrar/soltar, guardar borrador o publicar, editar (misma pantalla),
  eliminar con confirmación. Slug no cambia al editar (sin duplicados).
- API: GET /api/news (limit/page/all), POST/GET/PATCH/DELETE
  /api/news/[id], imagen pública /api/news/[id]/image.
- Migración: prisma/migrations/*_news. Seed: las 4 existentes (mismos slugs).
- Tras deploy: correr seed una vez para poblar news_posts.
----------------------------------------------------------------
- /login -> /portal deriva por rol (middleware protege /portal/*).
- ALUMNO (/portal/alumno): Centro MEC oficial + promedio interno,
  notas por período, asistencia (60 últimos), tareas de su
  bachillerato y estado de sus inscripciones.
- PADRE (/portal/padre): Centro MEC + por cada hijo vinculado su
  promedio, asistencia (presentes/total, ausencias), tareas
  pendientes y tabla de notas. Vinculación la hace Secretaría
  (tabla student_guardians).
- DOCENTE (/portal/profesor): filtro materia+período, nómina con
  nota actual, formulario cargar nota POST /api/grades (1-5),
  pasar asistencia POST /api/attendance
  (PRESENTE/TARDE/AUSENTE/JUSTIFICADO) y crear tarea
  POST /api/assignments. Lee GET /api/teacher/roster.
- ADMIN (/portal/admin): GET /api/admin/stats (usuarios por rol,
  solicitudes por estado, conteos) + bandeja GET/PATCH
  /api/enrollments (PENDIENTE->EN_REVISION->APROBADA/RECHAZADA;
  al aprobar el aspirante pasa a STUDENT).
- APIs nuevas: /api/attendance (GET/POST),
  /api/assignments (GET/POST) + /api/assignments/submit (POST
  alumno), /api/teacher/roster (GET docente/admin),
  /api/admin/stats (GET admin).
